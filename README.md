# Italian Edit

Интернет-магазин брендовой одежды и аксессуаров — [italian-edit.com](https://italian-edit.com).
Люкс-дропшиппинг: сток берётся у поставщика **BrandsGateway** (склады в ЕС и США),
плюс товары, которые менеджер заводит вручную из Италии через Телеграм-бота.

Репозиторий содержит **бэкенд** (`server/`). Сама витрина (тема Shopify) живёт
в Shopify и в репозиторий не входит — её устройство описано в разделе
[«Сайт (витрина Shopify)»](#сайт-витрина-shopify) как справка.

## Из чего состоит проект

| Компонент | Где живёт | Что делает |
|---|---|---|
| **Витрина** | Shopify (тема на базе Horizon) | Сайт, каталог, фильтры, оформление заказа. |
| **Телеграм-бот + сервер** | `server/` (один Node-процесс) | Бот заводит товары из Италии; сервер синкает каталог BG, дотегирует товары под фильтры витрины, снимает метку «новинка», проксирует заказы в BG. |
| **Приложение BrandsGateway** | Shopify App Store | В базовом режиме само заливает сток BG в Shopify, держит остатки и передаёт заказы поставщику. |

Бот и HTTP API — это **один процесс** (`npm run start`): один хостинг, одна кодовая база.

## Два канала поступления товаров

```
┌─ Канал 1: BrandsGateway (массовый сток, ЕС/США) ───────────────────────┐
│                                                                        │
│  IMPORT_MODE=app  (по умолчанию, тариф BG GROW):                       │
│     Приложение BG ──▶ заливает товары в Shopify (теги пола/категории,   │
│                        vendor=бренд), держит остатки, шлёт заказы в BG  │
│     Наш сервер   ──▶ ДОТЕГИВАЕТ склад EU/US (job shopify-tagger)        │
│                                                                        │
│  IMPORT_MODE=api  (тариф BG REST API/CSV):                             │
│     Наш сервер   ──▶ тянет каталог BG в свою БД (job bg-*-sync)         │
│                   ──▶ заливает в Shopify сам (job shopify-push)         │
│                   ──▶ проксирует заказы Shopify → BG                    │
└────────────────────────────────────────────────────────────────────────┘

┌─ Канал 2: Телеграм-бот (ручной, товары из Италии) ─────────────────────┐
│                                                                        │
│  Менеджер пишет в группу:                                              │
│     Название товара / Вариация (цвет) / Дизайнер / Наша цена           │
│     (без вариации — три строки; цена всегда последней)                 │
│  Бот ──▶ находит товар на официальном сайте бренда                     │
│      ──▶ отвечает карточкой (фото, цена бренда зачёркнута, наша цена)   │
│      ──▶ создаёт ЧЕРНОВИК товара в Shopify                             │
│  Менеджер проверяет черновик и публикует                              │
└────────────────────────────────────────────────────────────────────────┘
```

## Два режима импорта BrandsGateway (`IMPORT_MODE`)

Задаётся переменной `IMPORT_MODE` (см. `src/config.ts`).

- **`app`** — *текущий режим.* Тариф BG GROW/Scale, у которого нет REST API.
  Импорт, остатки и заказы делает **приложение BrandsGateway** прямо в Shopify.
  Наш сервер только **дотегивает** товары тем, чего приложение не ставит
  (склад EU/US), и снимает метку «новинка».
- **`api`** — тариф BG REST API/CSV. Всё делает **наш сервер** через API BG
  (`nova.shopwoo.com`): тянет каталог в PostgreSQL, заливает в Shopify,
  проксирует заказы. Требует переменные `BG_*` и `DATABASE_URL`.

> На момент написания у магазина тариф без API, поэтому каталог BG идёт через
> приложение (`app`), а наш `src/bg/*` (прямая интеграция) — на полке.

## Схема тегов — сердце всей системы

Витрина **не** использует Shopify-поле «Product type» или «Category». Вся
навигация, фильтры и умные коллекции держатся на **тегах товаров**. Поэтому
формат тегов обязан совпадать у всех трёх источников (приложение BG, бот, сервер).

| Тег | Что означает | Кто ставит |
|---|---|---|
| `EU` / `US` | Склад отгрузки — переключатель **Ships from** | приложение BG склад НЕ ставит → ставит наш `shopify-tagger` по бренду; бот ставит `EU`; api-push ставит из данных BG |
| `Women` / `Men` | Пол — переключатель **Shop**. Унисекс = оба тега сразу | приложение BG (при импорте), бот (по URL бренда), api-push (из поля gender BG) |
| `Bags`, `Shoes`, `Clothing`, `Accessories`, `Sweaters - Clothing`, … | Категория/подкатегория — пункты меню | приложение BG (свой формат тегов) |
| `category:bags`, `category:dresses`, … | Категория для товаров бота (легаси-формат) | бот (`src/shopify/categorize.ts`) |
| `designer:<бренд>` | Дизайнер (в нижнем регистре) | бот, `shopify-tagger`, api-push |
| `new` | В коллекции **New**; снимается через 14 дней | бот (`NEW_TAG`) |
| `italian-edit` | Коллекция «Italian Edit» (товары бота) | бот (`TG_COLLECTION_TAG`) |
| `delivery:manual-italy` | Доставка ручная из Италии | бот (`TG_DELIVERY_TAG`) |
| `bg` / `tg-bot` | Происхождение товара (BG или бот) | api-push / бот |

Ключевые функции формата — единый источник правды, чтобы теги не разошлись:

- `src/shopify/warehouse.ts` → `warehouseTag("eu") === "EU"`, `warehouseTag("us") === "US"`
- `src/shopify/gender.ts` → `genderTags("women") === ["Women"]`, `"unisex" → ["Women","Men"]`

> **Важно про склад.** Товар с европейского склада продаётся и в США — просто
> едет дольше. Переключатель Ships from даёт покупателю выбрать быструю доставку,
> а не ограничивает каталог по географии. Приложение BG склад тегом не помечает
> (для него склад — это fulfillment-локация), поэтому склад мы **выводим из бренда**:
> `src/shopify/warehouseByBrand.ts` — известные US-марки (Michael Kors, Coach,
> Tory Burch) → `US`, остальной люкс → `EU`. Список US-брендов — предположение,
> его надо сверять с реальным US-каталогом BG.

Скопировать `server/.env.example` → `server/.env` и заполнить.

| Переменная | Обяз. | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен Телеграм-бота от [@BotFather](https://t.me/BotFather). |
| `IMPORT_MODE` | — | `app` (по умолчанию) или `api`. |
| `SHOPIFY_SHOP` | для Shopify | Домен магазина, напр. `italian-edit.myshopify.com`. |
| `SHOPIFY_ADMIN_TOKEN` | * | Постоянный Admin-токen (`shpat_…`, легаси-приложения). |
| `SHOPIFY_CLIENT_ID` / `SHOPIFY_CLIENT_SECRET` | * | Client credentials (Dev Dashboard 2026+): клиент сам берёт токен на 24 ч. |
| `SHOPIFY_WEBHOOK_SECRET` | — | Секрет подписи вебхуков заказов Shopify. |
| `SERPER_API_KEY` | — | Google-поиск через serper.dev (2500 запросов бесплатно); без него — DuckDuckGo. |
| `DEFAULT_CURRENCY` | — | Валюта по умолчанию, если менеджер не указал символ (по умолчанию `EUR`). |
| `ALERT_CHAT_ID` | — | chat_id ТГ-группы для алертов об ошибках (узнать: команда `/chatid`). |
| `DATABASE_URL` | для api | PostgreSQL (нужна только режиму `api`). |
| `BG_EMAIL` / `BG_PASSWORD` / `BG_STORE_ID` / `BG_BASE_URL` | для api | Доступ к REST API BrandsGateway (Shopwoo). |
| `INVENTORY_CAP` | — | Правило «отдавать 1»: максимум остатка в Shopify (по умолчанию `1`). |
| `SHOPIFY_PUSH_BATCH` | — | Сколько товаров заливать за проход (по умолчанию `25`). |

\* Для Shopify нужен **либо** `SHOPIFY_ADMIN_TOKEN`, **либо** пара
`SHOPIFY_CLIENT_ID`+`SHOPIFY_CLIENT_SECRET` (см. `src/shopify/client.ts`).

## Сервер: фоновые задачи (планировщик)

`src/index.ts` регистрирует задачи в зависимости от режима. Простой планировщик
(`src/scheduler.ts`) гоняет их по интервалу; падение задачи шлёт алерт в ТГ, но
не роняет процесс.

| Задача | Режим | Интервал | Что делает |
|---|---|---|---|
| `bg-status-sync` | api | 5 мин | Синк остатков/статусов BG → БД (с учётом `INVENTORY_CAP`). |
| `bg-delta-sync` | api | 15 мин | Догрузка изменённых товаров BG → БД. |
| `bg-tracking-poll` | api | 30 мин | Опрос трек-номеров заказов, уведомления. |
| `shopify-push` | api | 1 мин | Заливка новых/изменённых товаров из БД → Shopify (батч). |
| `shopify-tagger` | **app** | 10 мин | **Дотегирует товары приложения складом `EU`/`US` по бренду + `designer:*`.** Идемпотентно. |
| `shopify-expire-new` | оба | 6 ч | Снимает тег `new` с товаров старше 14 дней (коллекция New). |

## Телеграм-бот

**Формат сообщения менеджера** (каждая часть с новой строки, цена — последней):

```
Ophidia mini bag
beige and ebony Supreme
Gucci
1200
```

(без вариации — три строки: название / дизайнер / цена)

**Что делает бот** (`src/bot/bot.ts` → `src/search/findProduct.ts`):

1. Определяет официальный домен дизайнера (`src/search/brands.ts`).
2. Ищет товар (Serper → Google, либо DuckDuckGo) на этом домене.
3. Скачивает страницу, парсит **JSON-LD** (schema.org Product) или OpenGraph —
   один парсер покрывает большинство брендов без индивидуальных скраперов.
4. Отвечает карточкой: фото, описание, цена бренда (зачёркнута) vs наша цена.
5. **Создаёт черновик товара в Shopify** (`src/shopify/draftProduct.ts`):
   - статус **DRAFT** (на витрине не виден, пока менеджер не опубликует);
   - наша цена — цена товара; цена бренда — `compareAtPrice` (зачёркнутая «до скидки»),
     но **только если валюта совпадает** с валютой магазина (иначе «скидка» вводила бы
     в заблуждение — бот честно предупреждает об этом в карточке);
   - фото грузятся отдельно (`uploadImages.ts`) — CDN брендов блокируют серверы Shopify,
     поэтому качаем сами и отдаём как base64;
   - теги: `tg-bot`, `new`, `italian-edit`, `delivery:manual-italy`, `EU`,
     `designer:<бренд>`, категория (`category:*` из названия/URL), пол (по URL).

**Команды:** `/start`, `/help`, `/check <запрос>`, `/chatid` (узнать chat_id для алертов).
Бот реагирует и на обычные сообщения группы, если они похожи на формат запроса —
для этого у бота должен быть **выключен privacy mode** (`/setprivacy` → `Disable` в @BotFather).

## Заливка и дотегирование товаров в Shopify

**`buildTags()`** (`src/shopify/products.ts`) — единая сборка тегов для товаров BG:
`["bg", warehouseTag(склад), ...genderTags(пол), "designer:<бренд>"]`.

**Режим `api` — `shopify-push`:** берёт очередь из БД (`productsToPush`), для каждого
товара создаёт (`productCreate`, статус ACTIVE) или обновляет (`productUpdate`) товар,
ставит цену/SKU варианта и остаток на первой локации. Ошибка одного товара не
останавливает остальные; результат пишется в `sync_log`.

**Режим `app` — `shopify-tagger`** (`src/shopify/tagStoreProducts.ts`): приложение BG
залило товары само, но без склада. Задача находит товары **без** тега `EU`/`US`
(запрос `-tag:'EU' -tag:'US' status:active,draft`) и добавляет:
- склад `EU`/`US` — из бренда через `warehouseForBrand()`;
- `designer:<vendor>` — если ещё нет.

Только **добавляет** теги, ничего не удаляет; идемпотентно и **самовосстанавливается**
(если приложение BG затрёт теги при ресинке — вернёт на следующем проходе).

## Заказы: Shopify → BrandsGateway

- **Режим `app`:** заказы BG-товаров передаёт **приложение BG само** — сервер не вмешивается.
- **Режим `api`:** вебхук `POST /webhooks/shopify/orders` (подпись проверяется по
  `SHOPIFY_WEBHOOK_SECRET`) → `forwardShopifyOrder()` оформляет заказ в BG и пишет в таблицу
  `orders`. Задача `bg-tracking-poll` подтягивает трек-номера и уведомляет.

Если заказ пришёл, а BG не настроен — сервер шлёт алерт в ТГ «оформите вручную».

## HTTP API

`src/api/server.ts` (Fastify), слушает `PORT` (по умолчанию 3000):

| Метод/путь | Назначение |
|---|---|
| `GET /health` | Проверка живости (для хостинга/мониторинга). |
| `POST /api/lookup` | Поиск товара: `{ title, designer, ourPrice, currency }` → `{ found, product, comparison }`. |
| `POST /webhooks/shopify/orders` | Вебхук заказов (только режим `api`, если задан секрет). |

## База данных

PostgreSQL нужна **только режиму `api`**; в режиме `app` сервер работает без неё
(бот и `shopify-tagger` в БД не заглядывают). Схема накатывается на старте из
`src/db/schema.sql`.

- **`products`** — каталог BG и его отражение в Shopify (цены оптовая/наша,
  склад `eu`/`us`, пол, `shopify_product_id`, статус, `push_error`, `manual_price`).
- **`orders`** — путь заказа Shopify → BG (bg_order_id, статус, трекинг).
- **`sync_log`** — журнал синхронизаций (видно, если что-то встало).

## Сайт (витрина Shopify)

> Файлы темы живут в Shopify (**Online Store → Themes**), не в этом репозитории.
> Ниже — устройство витрины как справка для будущих правок. Тема опубликована;
> черновиков сейчас нет.

**База темы:** Horizon (флавор «Ritual»). Правки внесены точечно в существующие
секции/сниппеты.

### Шапка — три ряда

Реализована в `sections/header.liquid` → `snippets/header-row.liquid`:

1. **Верхний ряд:** логотип слева, иконки (поиск, аккаунт, корзина) справа.
2. **Средний ряд:** переключатели каталога (см. ниже) — рендерится из
   `header-row.liquid` при `row == 'top'`.
3. **Нижний ряд:** пункты меню по центру.

### Переключатели (Shop + Ships from)

Средний ряд — `snippets/header-switchers.liquid`, каждый переключатель —
`snippets/browse-filter.liquid`:

- **Shop** — пол: All / Women / Men.
- **Ships from** — склад: All / EU / US.

Как работает: фильтрация идёт **маршрутом Shopify** `/collections/<handle>/<tag>`
по «сырым» тегам (`Women`, `EU` — без префикса). Два фильтра **комбинируются через `+`**:
выбор пола и склада вместе даёт `/collections/all/Women+EU`, причём переключение
одного фильтра **не сбрасывает** второй (параметр `other_tag` в `browse-filter`).
`snippets/browse-filter-persist.liquid` дотаскивает активный выбор при переходах по меню.

> Склад `EU`/`US` на товарах проставляет фоновая задача `shopify-tagger` (по бренду).
> Если тега нет ни на одном товаре, Shopify выкидывает его из URL — поэтому важно,
> чтобы тегировщик отработал (см. runbook).

### Меню

`Designers` · `New` · `Clothing` (+ подкатегории: Dresses, Tops, Swimsuits,
Jeans, Sweaters, Jackets & Blazers, Pants, Skirts, Shorts, Matching Sets,
Pajamas & Robes, Lingerie) · `Shoes` · `Bags` · `More` (Jewelry, Accessories, Kids).
Отдельной вкладки Dresses нет — платья внутри Clothing. Ювелирка — в More.

### Коллекции

- **Дизайнерские** (Gucci, Prada, Miu Miu, The Row, …) — по правилу **Vendor = бренд**.
  Есть отдельная индекс-страница дизайнеров.
- **Категорийные** (Bags, Shoes, Clothing и подкатегории, Accessories) — по тегам
  (тег приложения BG `Bags`/… ИЛИ легаси `category:*` от бота).
- **New** — по тегу `new`; товар выпадает через 14 дней (job `shopify-expire-new`).
- **Ships from Europe / USA** — по тегам `EU` / `US`.
- **Women / Men** — по тегам `Women` / `Men`.

Скрипт `scripts/setup-collections.ts` создаёт/чинит коллекции `Italian Edit`,
`Ships from Europe/USA`, `Women`, `Men`, беря теги из тех же `warehouseTag()`/
`genderTags()`, что тегируют товары — чтобы витрина и товары не разошлись по формату.
Дизайнерские и категорийные коллекции настраивались напрямую (не этим скриптом).

### Карусель дизайнеров

Coverflow-карусель карточек дизайнеров (в стиле Saks) под баннером-героем на главной:
неактивные карточки видны краем и наполовину скрыты за активной, скролл зациклен.

### Публикация правок темы

MCP-коннектор Shopify **не может писать в живую (опубликованную) тему** — только в
черновик. Порядок: продублировать тему → править черновик → менеджер публикует
вручную из админки.

## Запуск и деплой

```bash
cd server
cp .env.example .env      # заполнить BOT_TOKEN и (для Shopify) креды
npm install
npm run dev               # разработка (tsx watch)
# или
npm run start             # прод (один процесс: бот + HTTP API + планировщик)
```

**Хостинг:** сервер должен работать как постоянный процесс (Railway/Render/VPS).
Пока он крутится, задачи (в т.ч. `shopify-tagger`) идут сами. Остановится процесс —
дотегирование новых товаров остановится тоже.

## Операционные заметки (runbook)

**Прогнать `shopify-tagger` разово (не дожидаясь 10-минутного цикла).**
Например, после массового импорта в приложении BG. Создать во `server/` временный файл:

```ts
// server/_run-tagger.ts
import "dotenv/config";
import { loadConfig } from "./src/config";
import { ShopifyClient } from "./src/shopify/client";
import { tagStoreProducts } from "./src/shopify/tagStoreProducts";

const config = loadConfig();
const client = new ShopifyClient(config.shopify!);
console.log(await tagStoreProducts(client, { maxProducts: 500 }));
```

```bash
cd server && npx tsx _run-tagger.ts && rm _run-tagger.ts
```

Авторизация возьмётся из `.env` (client_credentials, если нет `SHOPIFY_ADMIN_TOKEN`).

> **Лаг индекса.** После массового `tagsAdd` Shopify `productsCount`/фильтры
> обновляются с задержкой ~минуту — доверяйте отчёту задачи (`tagged`/`failed`),
> а не мгновенному счётчику.

**Проверить, что фильтр Ships from наполнен:** товар должен нести тег `EU`/`US`.
Если `/collections/all/US` пуст — просто нет US-товаров (все текущие бренды — EU).

## Открытые вопросы

1. **Конвертация валют для compare-at.** Если цена бренда в EUR, а магазин в USD,
   зачёркнутая цена может вводить в заблуждение. Бот сейчас ставит compare-at только
   при совпадении валют. Автоконвертацию — обсудить и внедрить.
2. **US-сток.** У всех текущих товаров бренды европейские → фильтр `US` пуст. Чтобы
   появились «американские» товары, нужен реальный US-источник: либо US-склад BG
   (сверить список брендов в `warehouseByBrand.ts` с фактическим каталогом BG), либо
   отдельный US-поставщик (техника под `warehouse: "us"` уже готова).
3. **Product type / Category.** Пустые. Для витрины не нужны (навигация на тегах),
   но пригодятся для фидов Google/Meta/маркетплейсов, налоговой категоризации и SEO.
   Можно авто-заполнять из топ-тегов (Bags → Handbags и т.д.).
4. **Чистка контента от импорта BG.** В названиях/составах встречаются латинские
   названия сырья («Bos Taurus», «Ovis Aries»), в части описаний — коды артикулов.
   Кандидат на проход-«полироль» по аналогии с тегировщиком.
